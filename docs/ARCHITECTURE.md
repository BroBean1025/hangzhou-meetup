# 架构、数据与维护

浏览器载入 `public/index.html` 与带摘要的资源，同源请求 `/api/origin`、`/api/query`。`server.mjs` 提供静态页面并调用 `lib/metro-service.mjs`；所有供应商请求在后端发起。服务不读取他人的在线网站，不使用内置 Key。

## 数据责任

| 内容 | 主要来源 | 获取方式 |
| --- | --- | --- |
| 杭州站点、线路、网络图、最终站间路线/票价 | OpenMetro `cn-hangzhou` | 启动后按需请求并缓存 |
| 校门至地铁站步行/公交/骑行/驾车 | 高德 Web 服务 API | 有效缓存优先，未命中时用部署者 Key 请求 |
| 任意点目的地的末段步行 | 高德 Web 服务 API | 按需查询 |
| 杭海/绍兴轨道拓扑和时间 | `config/regional-network.json` | 已整理的跨城快照，不在日常轨道查询中反复请求高德 |
| 地图底图、校园区域、轨道曲线和校徽 | `data/` | 发布快照；前端构建不发网络请求 |

快照不保证当前运营状态。新增站点/校门/线路时要同时更新源数据、服务配置和前端目录，并重新核验，不可仅改一处站名。

## 缓存

独立版使用有界内存与相同请求合并，重启后内存缓存消失。地铁元数据约一天刷新；步行通常缓存 7 天，骑行 1 天，公交 15 分钟，驾车 5 分钟；校门综合结果不长于对应接驳缓存。`walking-snapshot.json` 仅在原始过期时间之前使用。

前端快照中的初始估时用于快速显示，不能称为实时查询。用户切换校门/方式或发起路线查询后，仍由服务返回可获得的结果。固定快照的更新时间见数据字段，不能将启动时间或构建时间当作原始数据更新时间。

## 东站与汇合点

火车东站和火车东站（东广场）作为同一目的地入口比较，但跨站区仍是方向明确的步行连接。`cross_station_seconds` 是 `transfer_seconds` 的子项，不能在总时间上重复相加。缺少室内几何时显示缺失，不人工补出轨道。

途中汇合要求不同来路汇入相同线路、相同方向的下一段；已同行的下游站不重复推荐，后来者加入会形成新候选。汇合到站时间复用当前校门的最短估时，不冒充当前目的地路线前半段的逐段累计时间；不包含等人和额外碰面步行。

## 前端图层

绘图、标注、校徽、固定地图控件、提示框和弹窗统一放入 Leaflet 图层。标注与固定控件使用视口坐标，移动/缩放时补偿 mapPane 位移；弹窗高于标注与操作面板。原生 dialog 和目的地下拉框在地图上方。新增绝对定位文字时不要重新挂在地图外层，否则可能再次盖住弹窗。

重叠行程保留真实轨迹，合并为共同路段；点击命中使用独立 SVG 层，防止站点 Canvas 截获路线点击。聚焦不新增供应商请求。

## 原项目与此发行版

本发行版只保留独立 Web 应用；没有 ChatGPT Sites 配置、Cloudflare 项目绑定或旧 Git 历史，也未附带 Codex Skill 运行环境。它覆盖当前网页功能，运行与二次开发不依赖 Codex。后续修改 `src/` / `lib/`，重建 `public/` 即可。
