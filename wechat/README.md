# Hangzhou MeetUp · 杭城同行 微信小程序

用微信原生地图选择目的地，同时比较多个校区、校门和地铁站出发的行程。项目目录为 `wechat/`，业务页面位于 `miniprogram/pages/map/`。

## 在本机预览

1. 安装 Node.js 22.13 或更新版本。在仓库根目录运行 `npm run wechat:dev`，保持终端开启。联调服务仅监听本机 8080 端口。Windows 上会优先使用环境变量或根目录 `.env` 中的高德 Web 服务 Key，其次在内存中读取当前用户已经保存的杭城同行桌面设置。只查地铁站间路线可以直接启动。
2. 打开微信开发者工具，选择「小程序 → 导入」，目录选本说明所在的 **wechat 文件夹**。本机可先使用测试号，已有小程序账号也可以填自己的 AppID。项目已带编译所需的地图数据与图标。
3. 使用默认的本地服务地址时，在开发者工具「详情 → 本地设置」启用「不校验合法域名」后点击「编译」。这项设置仅用于模拟器本地联调。
4. 在「起点」里展开学校，选择校区、校门和接驳方式，也可点「＋ 地铁站」。用顶部搜索框或点击地图选择目的地。「路线」可切换备选方案、查看接驳轨迹；「时间规划」可设定期望到达日期和时间、途中缓冲与汇合预留。

可用古荡、文三路两个地铁站作起点，选钱江路为目的地，检查武林门的同向汇合标志。把主起点设为其中一站，再切换到「交通枢纽」，即可查看到五个枢纽的估时。

## 在手机体验和发布

手机需要能够访问查询后端。模拟器配置的 `127.0.0.1` 在手机端指向手机本身。按已有部署条件任选一种接入方式。

| 后端 | 设置 |
| --- | --- |
| 微信云托管 | 使用仓库根目录作为构建上下文，选择 `tools/docker/Dockerfile`，容器端口 8080。在服务环境变量中填写 `AMAP_WEB_SERVICE_KEY`。把已关联小程序的云环境 ID 和服务名填到 `miniprogram/config.js` 的 `cloudEnv` 与 `cloudService`，两个字段均填后会使用 `wx.cloud.callContainer`。[微信云托管接入文档](https://docs.cloudbase.net/run/develop/access/mini) |
| 已有 HTTPS 后端 | 将同一套仓库服务部署到可访问的 HTTPS 域名，将其配置为微信公众平台的 request 合法域名。把 `apiBase` 改成该服务的 HTTPS 地址，两个云托管字段留空。 |

部署后可通过 `GET /api/health` 确认服务就绪与接驳配置状态。高德 Web 服务 Key 只放在后端。底图使用微信原生地图，轨道、校界、校门与接驳轨迹由应用叠加。

用实际小程序 AppID 在开发者工具点击「预览」，手机扫码检查地图选点、跨站区步行和到达时间规划。需要发给体验成员时，上传代码，在微信公众平台的版本管理中将开发版本设为体验版并添加成员。正式发布时按该账号后台的主体、类目和备案等要求补齐资料，提交审核，通过后发布。

## 从 GitHub 生成预览码或上传开发版

在仓库 Settings → Secrets and variables → Actions 中，将正式 AppID 保存为变量 `WECHAT_APPID`，将微信公众平台下载的代码上传密钥全文保存为 Secret `WECHAT_UPLOAD_KEY`。工作流使用微信官方 `miniprogram-ci` 和固定的 CI 机器人 1。

手机查询后端支持以下任一配置。可用仓库变量覆盖小程序源码中的默认联调地址。

| 接入方式 | 仓库变量 |
| --- | --- |
| 微信云托管 | `WECHAT_CLOUD_ENV` 和 `WECHAT_CLOUD_SERVICE` |
| 已部署的 HTTPS 服务 | `WECHAT_API_BASE` |

沿用本机默认地址且未配置上述变量时，工作流仍可预览、上传；手机端可以先看地图，查询面板会提示尚未接入后端。接入服务后重新运行即可启用路线查询。

上传 IP 白名单开启时，请让上传机器从已获准的公网 IP 出网。标准 GitHub 托管运行器的出口可能变化。已有固定出口的 HTTP 代理时，可以将其地址设为 Secret `WECHAT_CI_PROXY`，并将代理出口加入微信白名单。[微信 CI 文档](https://github.com/wechat-miniprogram/miniprogram-ci-dist)

工作流进入默认分支后，在 GitHub Actions 打开「微信小程序 · 预览与上传」，点击 **Run workflow**。选 `preview` 可从本次运行的 Artifacts 下载二维码；选 `upload` 并填写版本号，可上传开发版。在微信公众平台「版本管理」中选择体验版、添加体验成员。正式发布另行提审。[GitHub 手动运行说明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)

## 数据与维护

- 小程序复用现有 Node 路由服务、车站目录、线路走向、汇合判定及时间倒推算法。校区和轨道源数据变更后，在仓库根目录运行 `npm run build:wechat` 再编译。应用包内的源数据经过裁剪，仅携带需要展示的地图图层和五个枢纽的默认估时快照。
- 地图在微信端使用 GCJ-02，后端选点和返回轨迹使用 WGS84。坐标转换位于客户端边界。站内起算、从校门起算、到站与到地图选点的时间口径与网页版一致。缺少接驳数据时，结果会显示未知或失败原因。
- 静态轨道估时来自项目内的 OpenMetro 与区域网络快照；实时查询接驳时使用服务端高德接口。校区边界来自 OpenStreetMap。数据来源、校徽和素材说明见[第三方资源说明](../docs/legal/THIRD_PARTY_NOTICES.md)。
- 运行 `npm test` 可检查共享服务与小程序页面逻辑，包括站区合并、路网缩放、多起点汇合、时间倒推及异常状态。
